## 1. מה המערכת עושה?

המערכת מרכזת במקום אחד את כל הפניות שמגיעות לבר: מוואטסאפ, מאינסטגרם, בטלפון, מהאתר ומלקוחות שמגיעים פיזית. הצוות יכול לראות את הפניות, לסנן אותן ולטפל בהן ישירות מהטלפון, גם באמצע משמרת.

**סוגי הפניות שהמערכת מטפלת בהן:**
📅 הזמנת מקום · 😤 תלונה · 🎉 אירוע פרטי · 🔎 אבדות ומציאות · 💖 משוב · ❓ שאלה כללית · 🧑‍🍳 מועמדות לעבודה

## 2. איך המערכת עובדת?

| מסך | מה רואים שם |
|---|---|
| 🏠 **דאשבורד** | מדדים מרכזיים: פניות פתוחות, פניות חדשות היום, זמן תגובה ממוצע, שביעות רצון, הזמנות להערב. גרפים של פניות לפי יום, לפי סוג ולפי ערוץ. רשימה של פניות דחופות |
| 📋 **פניות** | רשימת כל הפניות, עם חיפוש ופילטרים לפי סוג, סטטוס, עדיפות וערוץ |
| 🔍 **פרטי פנייה** | נפתח בלחיצה על פנייה: בטלפון כחלון שעולה מלמטה, ובמחשב כפאנל צד. מציג את פרטי הלקוח וכפתורי חיוג ווואטסאפ. אפשר לשנות סטטוס, לשייך את הפנייה לנציג, לשנות עדיפות, להוסיף הערות ולבחור תשובה מוכנה מראש |
| 📅 **הערב** | כל ההזמנות של היום לפי שעה, ומספר הסועדים הצפוי |

| 🌙 **מזג האוויר: הערב ו-10 ימים** | בדאשבורד: מזג האוויר עכשיו, תחזית לפי שעה לשעות הפעילות (18:00–02:00), החלטה אם המרפסת פתוחה הערב, ו**תחזית ל-10 הימים הקרובים** עם החלטת מרפסת לכל ערב. במסך "הערב" מוצגת שורת סיכום. הנתונים מגיעים ממקור חיצוני חי, Open-Meteo |
| 🪴 **הזמנות למרפסת** | בהזמנת מקום בוחרים ישיבה בפנים או במרפסת. מרפסת אפשר לבחור רק אם בשעות הישיבה **הטמפרטורה לא יורדת מתחת ל-14° ולא צפוי גשם**. **אם אין תחזית, למשל כשהשירות לא זמין או בתאריך רחוק מ-10 ימים, אי אפשר להזמין במרפסת.** אם התחזית משתנה אחרי ההזמנה, מוצגת התראה להעביר את ההזמנה פנימה |
| ⚙️ **הגדרות** | חיבור ל-Airtable (מזהה base ומפתח גישה), בדיקת חיבור, ניתוק, וטעינת נתוני הדמה מחדש |

**מחזור החיים של פנייה:**
`חדש 🔵` → `בטיפול 🟡` → `טופל 🟢` → `סגור ⚪`

**טיפים לשימוש:**
- לחיצה על 🔔 בראש המסך מציגה מיד את כל הפניות החדשות.
- לחיצה על 🔄 טוענת מחדש את הנתונים מ-Airtable. כך רואים שינויים שאחרים עשו, או שינויים שנעשו ישירות ב-Airtable.
- כל שינוי סטטוס נרשם אוטומטית בהיסטוריית ההערות של הפנייה.
- תשובה מוכנה מראש **לא נשלחת באמת** ללקוח, כי זו מערכת לדוגמה. היא נרשמת כהערה, ופנייה חדשה עוברת ל"בטיפול".
- במכשיר שמוגדר למצב כהה, המערכת מוצגת אוטומטית בצבעים כהים.

**שמירת שינויים:** כל שינוי נשמר מיד ב-Airtable. המסך מתעדכן מיד, והשמירה מתבצעת ברקע תוך שבריר שנייה. אם השמירה נכשלת, למשל בגלל ניתוק מהאינטרנט, השינוי מבוטל ומופיעה הודעה.

**תאריכי הדמו:** נתוני הדמה נוצרים עם תאריכים יחסיים לרגע הטעינה, ולכן מיד אחרי טעינה יש פניות "מהיום" והזמנות "להערב". עם הזמן הנתונים מתיישנים. כדי לרענן אותם לוחצים **"טעינת נתוני דמה מחדש"** (בתחתית הדאשבורד או במסך ההגדרות).
⚠️ הפעולה מוחקת את **כל** הנתונים ב-Airtable, כולל פניות שהוספתם, וזה משפיע על כל המשתמשים.

**התחברות ואבטחה:** מפתח הגישה ל-Airtable **לא נמצא בקוד**. בכניסה הראשונה מכל דפדפן נפתח מסך ההגדרות, ושם מדביקים את המפתח פעם אחת. המפתח נשמר רק בדפדפן הזה. מי שנכנס לאתר בלי מפתח לא רואה שום נתון.

## 4. הוראות הפעלה

### שלב 0: חיבור ל-Airtable (פעם אחת בכל דפדפן)
1. יוצרים מפתח גישה ב-https://airtable.com/create/tokens ← **Create token**:
   - **Scopes:** `data.records:read`, `data.records:write`
   - **Access:** ה-base בשם **Neon Peach**
2. מעתיקים את המפתח. הוא מתחיל ב-`pat…`.
3. פותחים את האתר. מסך **⚙️ הגדרות** נפתח אוטומטית. מדביקים את המפתח ולוחצים **"שמירה ובדיקת חיבור"**.
4. אם החיבור הצליח, הנתונים נטענים והדאשבורד מוצג. 🎉

> 🔒 אל תשמרו את המפתח במחשב ציבורי. כדי למחוק אותו מהדפדפן לוחצים **"ניתוק"** במסך ההגדרות.

### הקמה של base חדש (רק אם מתחילים מאפס)
ה-base של Neon Peach כבר מוקם וטעון בנתונים. כדי להקים base חדש:
1. יוצרים ב-Airtable base ריק.
2. יוצרים מפתח עם 4 הרשאות: `data.records:read`, `data.records:write`, `schema.bases:read`, `schema.bases:write`.
3. מריצים מתיקיית הפרויקט (נדרש Node.js 18 ומעלה):
   ```bash
   AIRTABLE_TOKEN=pat... AIRTABLE_BASE_ID=app... node scripts/setup-airtable.js
   ```
   הסקריפט יוצר את 3 הטבלאות וטוען את נתוני הדמה.
4. מעדכנים את מזהה ה-base בקובץ `config.js`, או מזינים אותו במסך ההגדרות.

### אפשרות א': פתיחה מקומית (הכי פשוט)
1. מורידים את הפרויקט: **Code → Download ZIP** ב-GitHub, או משכפלים אותו:
   ```bash
   git clone https://github.com/yigaldf/aido-customer-services.git
   ```
2. פותחים את הקובץ `index.html` בדפדפן בלחיצה כפולה.
3. זהו, המערכת עובדת. 🎉

### אפשרות ב': שרת מקומי (לא חובה)
```bash
cd aido-customer-services
```
```bash
python3 -m http.server 8000
```
אחר כך פותחים בדפדפן את הכתובת http://localhost:8000

### אפשרות ג': פרסום באינטרנט עם GitHub Pages
1. ב-GitHub נכנסים ל-**Settings → Pages**.
2. בוחרים **Branch: main** ו-**Folder: / (root)**, ולוחצים **Save**.
3. אחרי כדקה המערכת תהיה זמינה בכתובת `https://yigaldf.github.io/aido-customer-services/`

### צפייה מהטלפון
פותחים את הקישור של GitHub Pages מהטלפון. הממשק מתאים את עצמו למסך: בטלפון יש תפריט ניווט בתחתית המסך, ובמחשב יש תפריט צד.

### דאשבורד בתוך Claude
יש גם דאשבורד שנפתח ישירות ב-Claude וקורא את הנתונים בזמן אמת מ-Airtable: https://claude.ai/artifact/V1dAAd2hdLxP6VJ9m7mDxJ
- הוא מציג פניות פתוחות, פניות חדשות היום, הזמנות להערב, שביעות רצון, גרפים לפי יום, סוג, סטטוס וערוץ, טבלת פניות פתוחות והזמנות להערב.
- הוא רק קורא נתונים. עדכונים ופניות חדשות נעשים באתר.
- הנתונים נקראים דרך החיבור (Connector) של Airtable ב-Claude, עם ההרשאות של מי שפותח את הדשבורד.
